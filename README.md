## 遊戲特色

- **可操作且會成長的 2.5D 夜市場景**：旋轉、縮放並瀏覽斜視角場景；主店會隨攤型升級變寬、加高，擴店則增加桌椅與燈籠。接手鄰攤後，場景會點亮所屬攤位並標示「夜嵐旗下」；客人、店員、爐火、煙霧、雨勢與活動效果也會隨營運呈現。點選攤位即可開啟工作台。
- **每日營運管理**：開門前管理菜單、食材庫存、設備升級與人員排班；開門後接待顧客、處理訂單與突發客訴。
- **左側場景即時營收回饋**：每筆主店交易會在對應攤位旁浮出金額，店長分店的自動銷售則從各自攤位顯示；固定營收牌只在接客前顯示，會平順累加商品銷售、小費與活動／手記收入，也可手動關閉至下一夜。補助、理賠應收、收銀盤盈及退款／短少另列，不混入商品銷售；動畫遵循暫停與系統減少動態效果設定，不增加存檔欄位。
- **有得有失的營運事件**：燈節與觀光活動可能帶來客流及活動 Bonus；雨勢、供應商調價、停電、稽查、秘密客與奧客會影響成本、服務或口碑。打烊盤點還可能發現假鈔／假幣、加價購短收、來源不明溢收或已確認的顧客溢付款。
- **宣傳成效與會計完整入帳**：節目採訪、名人探訪、短影音廣告與節目置入帶來不同成本與隨機曝光結果；付費宣傳列「行銷及宣傳費」，不會因曝光效果不佳而漏記支出。
- **收銀短溢調整**：假鈔／少收款借記「現金短溢損失」、貸記現金；無法確認來源的盤盈借記現金、貸記「現金短溢收益」。若確認是顧客被多收，會退款並列「退款及銷貨折讓」，不把應退回的款項當成營業利潤。
- **持續性的成本與投資**：納入攤位租金、擴店／併購租金、人事、食材、水電瓦斯、清潔、客訴、貸款利息等營運項目。設備購置、店面裝修與經營權會建立資產資料，並依耐用年限提列直線折舊或攤銷。
- **安全攤型升級**：各店面由「流動攤販」依序整修升級為「固定攤販」及「大排檔」，不能跳級；每次升級前須完成對應的瓦斯遮斷、排煙、冷鏈、營運設備與規模／人力條件。固定與大型攤型會提升接待量，同時增加持續能源成本；店面裝修與安全設備支出都列為資產並提列折舊。
- **人員與店面保險**：流動攤販員工自行安排基本保障，雇主可選擇加保職災；固定餐飲店增加食品業者產品責任險；大排檔由雇主編列職災、勞保、健保，並加投公共意外責任險。保險按每 30 夜一期，在第 1、31、61 夜等期初開門時列支並分科目記帳。
- **職安與食安事件**：營業中會隨機發生備料刀傷、熱鍋燙傷、送餐跌傷、顧客動線碰撞、餐點髮絲／小蟲異物及疑似諾羅病毒群聚。安全設備會降低事故機率；玩家先處理人員照護、顧客補償、停售與清消，再依本期已繳保費對應的有效保障選擇申請理賠或自行負擔。異物事件會暫時下架受影響菜色；重大食品安全事件會停業一夜並讓口碑、熟客與後續客流承受影響。
- **理賠應收與收款**：職災、公共意外及產品責任事件的模擬理賠，以「應收保險理賠款」借記、以「保險理賠收入」貸記，兩夜後收款並沖銷應收；照護、補償、清消支出分別記入職災、顧客意外或食品安全費用科目。若本期沒有已生效的對應保障，玩家不能選擇保險理賠。
- **升級菜色與家鄉秘笈**：主店升級固定攤販及大排檔會各自免費解鎖一道新佳餚；接手的炸物、果物、甜食、遊戲體驗店則隨攤型解鎖不同升級商品和售價。熟客多次獲得合胃口的服務後，可能免費分享家鄉菜秘笈；菜色免費解鎖，但販售仍需消耗既有食材並列銷貨成本。
- **離職與孤兒保單**：已繳費期內有雇主承保的全職夥伴離職時，遊戲依未到期日數估算可回收保費，先列孤兒保單待辦；每期最後一夜的期末調整工作底稿借記「應收保險退費款」、貸記對應保險費用，次期首夜模擬收到退款並沖銷應收。
- **每週經營決策**：每完成七夜進入週轉決策，可選擇擴店、招募人手、併購同業或保留現金；投資會持續影響日後客流、固定成本與資產。
- **業態專屬分店商品與價格**：接手港口炸物、山海果物、花生糖舖或彈珠小屋，各自有專屬商品、備料單位、進貨成本、售價與設備加價；不再讓不同店面共用同一套商品與定價。
- **可管理的接手分店**：併購後的攤位會成為獨立店點，不再只是品牌聯盟的被動加成。可逐店補該業態的專屬備料、升級設備、開店或暫停；由老闆照看的分店每夜最多接一筆生意。
- **店長自動營運與總部決策**：主店加上至少一間正在營業的分店後，可在週決策聘請店長（招募訓練 NT$ 420 起、每夜薪資 NT$ 62）。店長自動排班、提高接待量並處理例行營運；備料售罄會自動暫停分店，玩家仍需補貨。每週若遇設備異常、分店客訴或慶典邀約，玩家只需決定維修、補償或活動投入等重大事項；也可解除店長、改回自營。
- **品牌聯盟與供應優勢**：擴店並接手兩間同屬餐飲或遊戲體驗的分店，可建立夜市品牌聯盟，取得客流與採購優惠等長期效果。
- **經濟原理與營運取捨**：經營決策呈現固定成本、變動成本、資本投資、庫存成本、現金流與融資成本；擴張可增加接待能力或開啟分店收入，同時帶來租金、人事與能源等持續支出。
- **持續流動的遊戲世界**：故事與市集日曆每 30 夜進入下一期循環，週決策持續進行；第 30 夜不是遊戲結束，而是新的報表期間與故事里程碑。
- **港邊里程碑成就**：以攤型成長、營運節奏、職安食安、分店、菜色、熟客與帳務閱讀記錄 26 項重要足跡。成就只作收藏與敘事，不發現金或改變經濟；解鎖時以輕量提示回饋，完整一覽可由頁尾按鈕開啟彈窗，已解鎖項目以全彩呈現、未解鎖項目採灰階。舊存檔會靜默補登可由現況推導的成就；重啟世界時一併清空。
- **營運紀錄與財務報表**：可查前一日日記簿與會計分錄、每週試算工作底稿及每 30 夜的期末調整底稿；每 30 夜結算綜合損益表、權益變動表、資產負債表及現金流量表，也可檢視會計科目表與資產清冊。
- **成就一覽**：頁尾「港邊里程碑」會開啟可分類篩選的彈窗；已解鎖成就顯示解鎖夜次與期數，未解鎖項目以灰階和提示呈現，隱藏故事在解鎖前不揭露名稱。
- **遊戲說明**：頁面底部的「遊戲說明」可查閱攤型、成本、保險、離職保費回收、職安食安、宣傳效果、秘密評鑑及收銀短溢會計處理。
- **瀏覽器自動存檔與重啟**：遊戲進度儲存在目前瀏覽器的本機儲存空間；「遊戲說明」最下方可重新開始，經二次確認後清除目前、舊版與損壞備份進度並回到第 1 夜。若偵測到較新版存檔，重啟只影響記憶體中的遊戲狀態，不會刪除或覆寫該存檔。

## 會計模型說明

遊戲採用**IFRS 導向的教育性模擬**，以借貸平衡分錄整理營運資料，並呈現主要財務報表。科目代碼為本專案的內部編號，不是 IFRS 官方科目編碼；包含保險費率、未到期保費的按日比例與退費流程在內，均為便於遊玩的簡化模型，不代表實際保險契約、法定費率或法規遵循結果。模型亦未涵蓋完整財報附註、所有稅務與會計政策選擇或其他綜合損益項目，不應視為正式會計或稅務工具。

遊戲把經濟概念轉成可讀、可操作的經營選擇，而非完整的總體經濟或真實市場預測模型。重要效果會分別記入現金、營運帳本與內部科目，讓玩家能比較「今晚賺多少」與「長期能否承擔」。

| 經濟概念 | 遊戲中的對應 | 經營上的取捨 |
| --- | --- | --- |
| 固定成本與營運槓桿 | 租金、人事、水電瓦斯、分店營運費、店長薪資及定期保費依日或保險期計提；擴桌、招募、併購會增加後續固定支出。 | 擴張提高接待／營業能力，但客流不足時，固定成本仍會侵蝕利潤。每週也可選擇暫不投資、保留現金。 |
| 變動成本與毛利 | 每道料理、各業態分店商品各有售價、進貨成本與銷貨成本；商品售出才將對應庫存成本認列為費用。 | 比較商品毛利與備料需求，避免只看營收、忽略食材成本或缺貨。 |

### 收入、成本與現金流的區分

- **補貨不是立即的銷貨成本**：採購時借記存貨、貸記現金；商品售出時才依存貨成本認列銷貨成本並沖減存貨。這讓現金流出與當期獲利不會被混為一談。
- **設備費不是一次全部當作當期費用**：符合資產條件的設備、店面裝修與經營權進入資產清冊，後續按設定年限折舊／攤銷；折舊影響損益，但不是當期現金付款。
- **活動、補貼與保險理賠分開呈現**：活動 Bonus、補助、服務小費與理賠不併入商品銷售額；理賠先列應收，兩夜後模擬收款，避免將尚未收現的理賠直接當成現金。
- **保險與保費退回按期間處理**：保費在每 30 夜一期的首日計提；雇主承保員工離職形成的未到期保費回收，於期末調整工作底稿列應收，次期模擬收款。

## 事件設計與平衡原則

事件採「**可預期的節奏＋有選擇的代價＋可準備的風險**」：30 夜敘事日曆提供節慶、雨勢、供應商、停電及稽查等不同衝擊；市集公告卡依週期排定，並非每夜都隨機要求玩家做額外決策。事件可透過升級、備料、保險或選項減輕，但多數處置仍會消耗金錢、客流、口碑或時間。

| 事件／機制 | 目前效果 | 平衡方式與反制 |
| --- | --- | --- |
| 燈節與活動 | 增加一桌活動客，並對每位客人提供 NT$ 35 活動 Bonus。 | 額外收入受備料與接待能力限制；活動 Bonus 與商品銷售、服務收入分開入帳。 |
| 觀光客暴增公告 | 選擇支付 NT$ 100 行銷費，增加兩桌客人並提升口碑，或維持原規模。 | 玩家可按庫存、員工與當晚客流預估決定是否加開接待，不強迫所有局面都採用同一選項。 |

## 本機執行

專案使用原生 JavaScript，無需安裝第三方套件或建置流程。使用 Node.js 執行測試：

```bash
npm test
```

可使用任一靜態檔案伺服器提供 `dist/` 目錄，例如：

```bash
python -m http.server 4173 --directory dist
```

接著瀏覽 `http://localhost:4173`。

## 架構與資料安全

- **規則與瀏覽器啟動分開**：`dist/engine.js` 集中處理可測試的經營規則；`dist/game.js` 負責瀏覽器事件、場景與對話框流程，並明確匯出 `boot()` 供啟動整合測試使用。
- **介面按責任拆分**：`dist/ui.js` 管理營運與攤位面板；帳務、日記簿與報表由 `dist/ui/reports.js` 負責，場景物件與事件效果則維持在 `dist/scene/` 子模組。
- **狀態更新方式**：目前引擎刻意採用 mutable state，場景、面板與規則共用同一份遊戲世界。瀏覽器中的遊戲操作會在執行前建立 JSON 快照；若記帳或其他操作意外 throw，便復原快照、重新渲染並回報玩家，不寫入半套狀態。`postJournal` 的借貸檢查仍採 fail-fast，錯誤由操作邊界接住。
- **存檔版本與復原**：localStorage 存檔帶有 `schemaVersion: 5`，舊版資料透過 `normalizeState` 遷移；新存檔增列公告卡曝光結果與收銀事件相容欄位。壞格式存檔會盡力保留至 `.corrupt-backup` 再開啟新進度。較新版存檔不會被舊版遊戲覆寫；儲存空間不足或瀏覽器拒絕存取時，狀態列會顯示原因。
- **規模上限**：手記最多保留 8,000 夜、分錄最多保留 8,000 筆、每週工作底稿最多 104 期、月報最多 36 期，以控制長期存檔體積。
- **隨機與測試**：`createGameEngine(state, { random })` 可注入亂數來源，讓事故與秘笈等機率流程可重現；遊戲資料目前使用單一 mutable state，不是事件溯源／時間旅行架構。

## 專案結構

- `dist/index.html`、`dist/styles.css`：遊戲頁面結構與視覺樣式。
- `dist/data.js`：菜單、顧客、事件、價格與場景設定。
- `dist/campaign.js`：30 夜故事日曆、市集公告卡、宣傳合作排程、每週決策與結局條件。
- `dist/state.js`：遊戲存檔、遷移、營運狀態、成本與事件規則。
- `dist/engine.js`：可注入亂數的經營引擎，處理服務流程、打烊突發事件、週決策、事故／保險與分店自動營運。
- `dist/safety.js`：攤型、安全升級條件、接待容量、期初保險費與保障規則。
- `dist/accounting.js`：內部科目表、借貸分錄、資產折舊／攤銷與報表結算。
- `dist/game.js`：可測試的遊戲規則與瀏覽器互動流程。
- `dist/scene.js`：斜視投影、相機、場景合成、命中測試與操作控制。
- `dist/scene/objects.js`、`dist/scene/effects.js`：場景物件與事件特效繪製。
- `dist/ui.js`：以 DOM 節點建立的管理面板、攤型／保險管理、期末工作底稿與報表介面。
- `dist/ui/reports.js`：日記簿、週底稿、期末調整與週期財務報表的節點渲染。
- `dist/app.js`：瀏覽器啟動入口。
- `tests/game.test.js`：遊戲規則、存檔、相機、經濟循環與會計報表測試。
