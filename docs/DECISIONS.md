# 設計決策紀錄

本檔只記錄會影響架構與遊戲規則的決策。調整決策時，保留原始理由，並新增後續紀錄或更新狀態，避免悄悄改變系統假設。

## ADR-001｜採用靜態原生前端與 Canvas 2D

- **狀態：** 已採用
- **決策：** 使用 HTML、CSS、JavaScript ES modules 與 Canvas 2D；網站以 `dist/` 為靜態發布目錄。
- **理由：** 遊戲核心可在瀏覽器端運作，不需伺服器端儲存即時遊戲狀態；模組可由 Node 測試執行，場景可程式化繪製。
- **代價：** 無框架提供的型別與元件邊界；需自行維護模組責任、DOM helper 與測試慣例。
- **重新評估條件：** 引入多人連線、帳號雲端存檔或大量資產／場景內容時。

## ADR-002｜單一 mutable state，重要動作採快照還原

- **狀態：** 已採用
- **決策：** 引擎直接更新同一份 root state；瀏覽器操作在執行前建立快照，遇到例外時還原原 root 物件。
- **理由：** UI、引擎與 Canvas 場景需要讀取同一個目前世界；以目前規模而言，可避免大量複製及同步層。
- **代價：** 測試需隔離 state；動作不能天然提供時間旅行或多人衝突處理。JSON 快照要求 state 維持純資料結構。
- **防線：** 預期失敗使用 `{ ok: false, changed: false, message }`；非預期錯誤在操作邊界還原並提示。會計分錄借貸不平衡採 fail-fast。
- **重新評估條件：** state 規模明顯成長、需要 undo／多人同步，或 JSON 快照成本成為可觀測瓶頸。

## ADR-003｜依領域與呈現責任拆分模組

- **狀態：** 已採用並持續演進
- **決策：** 將設定、營運狀態、引擎、會計、安全、週期、UI 報表及 Canvas 物件／特效分離。
- **理由：** 新規則可在不改動主要渲染流程的前提下擴充；純規則路徑可使用 Node 測試。
- **代價：** 模組間的依賴與 state 欄位契約需要文件化；少數 UI 檔案仍較大。
- **重新評估條件：** 模組間出現循環依賴、同一責任持續跨檔散落，或單檔變更衝突頻繁。

## ADR-004｜敘事以 30 夜為一期，經營世界持續前進

- **狀態：** 已採用
- **決策：** 30 夜作為故事與會計週期；完成期末結算後繼續下一期，而不是在第 30 夜停止。
- **理由：** 保留階段性敘事與財報節點，同時支援長期經營、每週投資及持續性店面成本。
- **代價：** 故事日曆按期循環；跨期存檔、保險與會計結帳需處理全域夜數和週期日的差異。
- **重新評估條件：** 加入更長主線或可選劇情章節時；會計期間仍需維持明確結帳規則。

## ADR-005｜會計採遊戲內部科目與可勾稽分錄

- **狀態：** 已採用
- **決策：** `accounting.js` 維護內部科目表，每筆分錄強制借貸平衡；資產購置、折舊／攤銷、保險應收、借款及報表以此為資料來源。
- **理由：** 讓營運現金流、損益和資產負債可在遊戲中對照，並提供可測試的財務資料結構。
- **代價：** 遊戲現金、存貨／負債與 accounting balances 是跨欄位的雙重呈現，所有變更路徑都需維持一致。
- **防線：** 主要營運路徑有勾稽測試；分錄不平衡不得被靜默忽略。
- **範圍界線：** 科目編碼屬本專案內部編號，報表只模擬主要呈列，不宣稱完整財報或法定合規。

## ADR-006｜攤型升級由安全條件與持續成本共同約束

- **狀態：** 已採用
- **決策：** 攤位依流動、固定、大排檔逐級升級；升級需滿足設備／規模條件，並伴隨容量、能源、保險及折舊等影響。
- **理由：** 將視覺擴張與風險、產能及持續成本相連，避免升級只帶來無條件收益。
- **代價：** 多店時需對每個 outlet 分別驗證安全、員工及保險資料。
- **重新評估條件：** 攤型或安全設備新增時，需一併更新資格檢查、UI 提示、記帳與測試。

## ADR-007｜不同業態的分店資料彼此區分

- **狀態：** 已採用
- **決策：** 分店商品、備料、價格、設備與升級菜色由 outlet 類別決定；店長自動化只處理例行營運，重大事件仍由玩家決定。
- **理由：** 讓併購、管理與品牌聯盟形成可辨識的業態策略，不讓所有分店使用同一張商品表。
- **代價：** 新增業態需同步新增產品資料、庫存正規化、UI 管理、事件處理及測試。
- **重新評估條件：** 分店數量或業態組合超出固定場景資料的合理範圍。

## ADR-008｜先以既有場景內的視覺成長反映進度

- **狀態：** 第一階段已完成；更大場景待評估
- **決策：** 主店尺寸／結構由攤型與 expansions 推導；併購透過既有鄰攤的亮度、標示與短暫接手回饋呈現。場景座標不寫入存檔。
- **理由：** 使用現有五攤資料與繪製管線，讓經營進度有視覺回饋，同時避免只擴畫地圖但沒有對應規則。
- **代價：** 店面可能會在固定地圖範圍內變大；可營運攤位數仍受既有資料限制。
- **後續方向：** 相機活動範圍與遠景補強屬下一階段；新增可探索區塊前，必須先定義可經營內容、路徑與存檔資料。

## ADR-009｜尊重作業系統減少動態效果偏好

- **狀態：** 已採用
- **決策：** 場景動畫可暫停；偵測到減少動態效果偏好時抑制動態更新，接手提示亦不播放位移淡出。
- **理由：** 動畫用於傳達經營狀態與場景生命感，不應凌駕使用者的系統設定。
- **重新評估條件：** 增加新的持續動畫或場景特效時，需保留等價靜態狀態與 reduced-motion 行為。

## ADR-010｜不可逆重啟採二次確認並保護較新版存檔

- **狀態：** 已採用
- **決策：** 重啟入口放在遊戲說明末尾；第一次按下只開啟確認對話框，明確確認後才清除目前、舊版及損壞備份存檔並重置同一份記憶體 state。
- **理由：** 重啟會刪除本機進度，必須讓玩家理解影響並可在確認前取消。
- **安全邊界：** 若載入時偵測較新版 schema，禁止刪除或覆寫該存檔；仍重置目前載入的記憶體世界，並提示較新版存檔保留。
- **失敗回饋：** 儲存空間不可用或任一已知存檔 key 無法清除時，仍更新目前世界，但明確提示本機資料清除／儲存未完整完成。
- **重新評估條件：** 新增存檔 key、雲端存檔或多存檔槽時，重啟的目標範圍與保護策略需同步更新。

## ADR-011｜港邊里程碑只記錄足跡，不介入經濟

- **狀態：** 已採用
- **決策：** 首版提供 26 項結構性成就，從攤型、營運、風險、分店、菜單、故事與帳務閱讀等現有狀態判定；已解鎖項目儲存 id、夜次與期數。列表以獨立彈窗呈現，解鎖時使用輕量提示與待查看標記，不彈出強制阻斷視窗。
- **理由：** 成就用於保留經營記憶與引導探索，不應讓玩家為刷成就改變正常經營，也不應破壞教學用的成本與帳務關係。
- **防線：** 不提供現金、免租、折扣或其他數值獎勵；可由舊存檔現況推導的成就靜默補登；未解鎖成就以灰階呈現，隱藏故事在解鎖前不透露內容；明確重啟時與世界進度一併清空。
- **存檔：** schema 由 3 升至 4，只儲存解鎖紀錄、提示佇列與少量帳務閱讀旗標，不複製營運統計或事件歷史。
- **重新評估條件：** 若增加跨世界永久圖鑑、純裝飾收藏或新的結局成就，應獨立定義永久資料的保留範圍與重啟政策，不改變首版零經濟獎勵原則。

## ADR-012｜收銀差異按差異原因入帳，曝光支出不依結果回沖

- **狀態：** 已採用
- **決策：** 打烊的假鈔／假幣與加價購短收認列現金短溢損失（5510）；來源不明的盤盈才認列現金短溢收益（4040）；已識別的顧客溢付款以 4090 銷貨折讓退款處理，不認列收益。廣告、節目置入與接待成本均按發生日列為 5410 行銷及宣傳費，成效隨機但不改寫已發生支出。
- **理由：** 保留「現金差異原因」與「可辨認的顧客退款義務」之間的區別；同時使玩家能比較曝光結果與實際投入，而不是只在成功時認列成本。
- **平衡與驗證：** 收銀短溢每夜最多觸發一項；秘密客與稽查為獨立小機率事件。亂數可注入固定序列；測試需要驗證現金、營業帳本、借貸平衡及跨期結轉。
- **存檔：** schema 升至 5，新增當日公告卡曝光結果及短溢帳本欄位；舊版存檔在正規化時補齊，新欄位不可信任未對應當日公告的結果資料。
- **重新評估條件：** 若新增未支付退款負債流程、退款延遲或按收銀員追蹤差異，應重新檢視短溢與退款的帳務事件模型。

## ADR-013｜交易收入在場景中即時可見，但不改變帳務來源

- **狀態：** 已採用
- **決策：** 場景提供固定於視窗的「今晚營業收入」摘要，只在接客前的準備階段顯示，且玩家可手動關閉至下一夜；分列商品銷售、小費與活動／手記收入。主店與店長分店另以攤位錨點浮標回饋每筆收入。補助、理賠應收、收銀盤盈及現金短溢／退款各自標示，不混入商品銷售額；營收牌不代表淨利，成本與損益仍由每日帳本及結帳計算。
- **理由：** 讓場景互動與經營數字形成可讀的即時回饋，同時避免把現金流入、營業收入、短溢與淨利混為一談。
- **防線：** `scene/revenue.js` 只讀帳本，所有平滑數字與浮標均為暫態，不持久化或變更交易；動畫尊重暫停及 `prefers-reduced-motion`，螢幕閱讀器只在交易事件時播報。
- **重新評估條件：** 若加入多幣別、分店收入分攤、延遲退款／理賠或玩家自訂 HUD，需重新檢查分類、排序與語意標籤。

## ADR-014｜以每週經營焦點串連每日服務與 30 夜結帳

- **狀態：** 已採用
- **決策：** 首週從「服務來客」開始；之後每次週決策依玩家選擇建立對應焦點：擴店追蹤服務人次、招募追蹤合胃口的服務、併購追蹤分店商品銷售夜、保留現金追蹤現金為正且未新增週轉借款的夜數。每日進度以小型可存取進度卡呈現，週結算結果寫入日記簿及工作底稿；30 夜財務報表仍是較長期的回顧節點，可能與七夜焦點週的邊界不一致。
- **理由：** 讓既有的備料、服務、週投資與會計回顧互相接續；用可見目標與明確結算建立節奏，而不是增加一套與日常操作分離的任務清單。
- **防線：** 焦點追蹤既有營運資料，不增加必做操作或帳務交易；完成獎勵限口碑 +2、熟客 +1，未完成沒有現金、口碑或進度懲罰。各焦點目標保持可達，日常營運受缺貨或客流影響時不會鎖死週決策。
- **存檔：** schema 升至 6，新增目前週焦點及進度；日記與週底稿保存結算摘要。舊存檔按當週已記錄決策遷移，缺少歷史資料時從下一個玩家選定的週方向開始追蹤。
- **重新評估條件：** 若新增每日行動點、長期任務線或跨週永久獎勵，需重新檢查焦點是否增加操作負擔、獎勵是否造成熟客／口碑過度膨脹，以及週與 30 夜結帳的節奏是否仍清楚。

## ADR-015｜跨期敘事回聲、選用音景與靜態場景降載

- **狀態：** 已採用
- **決策：** 新一期第一夜從既有期末結局及最近一次週決策推導一段章節敘事；不新增存檔欄位，也不影響玩法數值。以 `audio.js` 提供預設關閉、玩家可自行啟用的程序化港邊音景和短音效；使用者暫停場景或系統減少動態效果時，場景靜態重繪頻率最多每秒 10 次。
- **理由：** 讓持續營業世界能記得上一期的經營結果，並補足原先只有短促操作音的聽覺層；同時保持音訊使用者控制權，避免靜止場景持續做每影格繪製。
- **防線：** Web Audio 僅在玩家互動後建立；音景無外部資產、網路或新套件依賴，關閉即停止音景節點，分頁隱藏時暫停音訊。重繪節流不改變命中測試、場景狀態或遊戲時間；任何效能提升聲稱需另以實機量測支持。
- **驗證：** 測試前期日曆文案維持不變、跨期文案依結局與決策分歧、無音訊時不建立 AudioContext、開啟後可停止音景；另檢查 paused/reduced-motion 畫面仍可操作。
- **重新評估條件：** 若新增真人音檔、背景音樂或更多聲道，需先確認授權／體積、音量混音、靜音偏好與低階裝置成本；若場景規模擴大，需量測 frame-time 後決定快取或視野裁切，而非預先堆疊優化。

## ADR-016｜以小步搬移降低引擎、UI、測試與樣式的維護熱點

- **狀態：** 第一輪已採用；其餘拆分持續進行
- **決策：** 保持原生 ES modules 與現有 HTML 入口，將分店／店長規則移至 `engine/branches.js`，將事故、宣傳與打烊事件移至 `engine/events.js`，將備料／設備／排班面板移至 `ui/preparation.js`。依測試領域拆分測試檔；由 `styles.css` 以固定順序匯入語意化 CSS partial。
- **理由：** 先縮小高變動責任的單檔範圍，避免重寫既有規則或引進不必要的打包器；單一 state、DOM 掛載方式及公開頁面路徑維持不變。
- **防線：** 本次拆分以搬移既有函式為主；跨模組的引擎 closure 依賴透過 factory 參數明確傳入。現有 `npm test` 作為行為相容檢查，CSS partial 的匯入順序須保持原始 cascade。
- **目前限制：** `engine.js`、`ui.js` 仍負責多個領域的協調與呈現，後續可再依服務流程、週決策或 dialog/tab 邊界抽離；不把檔案數量當作品質指標。
- **重新評估條件：** 新增大型遊戲領域、修改跨模組 state 更新方式，或單檔再次成長到難以局部理解時，先確認責任邊界與測試所有權，再拆下一個模組。

## ADR-017｜加密每日、每週與每期回饋，不增加經濟壓力

- **狀態：** 已採用
- **決策：** 準備階段可回顧前一夜實際現金簿；每週焦點跨過一半與達標時給一次文字提示，接近目標未完成時呈現差距；週決策卡預覽已知固定成本、固定支出續航估算與該選項會開啟的焦點；食安事件提供恢復倒數；公開且有明確單一計數器的成就提供進度；新期開場連結上一期敘事及財報；連續好評服務使用逐階音高提示。
- **理由：** 將已有的日記、成本、週焦點、恢復規則、成就和跨期資料變得容易察覺，讓夜／週／期的進展彼此相連，而非再新增平行任務、經濟系統或永久成長貨幣。
- **防線：** 焦點與音階不改變經濟；成本預覽使用明確「估算」語意並揭露不含補貨、事件與浮動人事；現金簿清楚標示前一夜，不將未營業的當晚標成已實現收入；隱藏成就在解鎖前不揭露名稱或進度。
- **資料與相容性：** 日記簿允許新增可選 `cashbook` 摘要，讀取端先使用保存摘要，再以既有會計日記帳回補；舊日記仍顯示有限度的營運資料。週焦點提示佇列只存在引擎執行期；不新增存檔 schema 欄位。
