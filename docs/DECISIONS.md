# 設計決策紀錄

本檔只記錄會影響架構與遊戲規則的決策。調整決策時，保留原始理由，並新增後續紀錄或更新狀態，避免悄悄改變系統假設。

## ADR-001｜採用靜態原生前端與 Canvas 2D

- **狀態：** 已採用
- **決策：** 使用 HTML、CSS、JavaScript ES modules 與 Canvas 2D；網站以 `dist/` 為靜態發布目錄。
- **理由：** 遊戲核心可在瀏覽器端運作，不需伺服器保存即時遊戲狀態；模組可由 Node 測試執行，場景可程序化繪製。
- **代價：** 無框架提供的型別與元件邊界；需自行維護模組責任、DOM helper 與測試慣例。
- **重新評估條件：** 引入多人連線、帳號雲端存檔或大量資產／場景內容時。

## ADR-002｜單一 mutable state，重要動作採快照還原

- **狀態：** 已採用
- **決策：** 引擎直接更新同一份 root state；瀏覽器操作在執行前建立快照，遇到例外時還原原 root 物件。
- **理由：** UI、引擎與 Canvas 場景需要讀取同一個目前世界；當前規模下可避免大量複製及同步層。
- **代價：** 測試需隔離 state；動作不能天然提供時間旅行或多人衝突處理。JSON 快照要求 state 維持純資料結構。
- **防線：** 預期失敗使用 `{ ok: false, changed: false, message }`；非預期錯誤在操作邊界還原並提示。會計分錄借貸不平衡採 fail-fast。
- **重新評估條件：** state 規模明顯成長、需要 undo／多人同步，或 JSON 快照成本成為可觀測瓶頸。

## ADR-003｜依領域與呈現責任拆分模組

- **狀態：** 已採用並持續演進
- **決策：** 將設定、營運狀態、引擎、會計、安全、週期、UI 報表及 Canvas 物件／特效分離。
- **理由：** 新規則可在不改動主要渲染流程的前提下擴充；純規則路徑可使用 Node 測試。
- **代價：** 模組間的依賴與 state 欄位契約需要文件化；少數 UI 檔案仍較大。
- **重新評估條件：** 模組間出現循環依賴、同一責任持續跨檔散落，或單檔變更衝突頻繁。

## ADR-004｜敘事以 30 夜為一期，經營世界持續前進

- **狀態：** 已採用
- **決策：** 30 夜作為故事與會計週期；完成期末結算後繼續下一期，而不是在第 30 夜停止。
- **理由：** 保留階段性敘事與財報節點，同時支援長期經營、每週投資及持續性店面成本。
- **代價：** 故事日曆按期循環；跨期存檔、保險與會計結帳需處理全域夜數和週期日的差異。
- **重新評估條件：** 加入更長主線或可選劇情章節時；會計期間仍需維持明確結帳規則。

## ADR-005｜會計採遊戲內部科目與可勾稽分錄

- **狀態：** 已採用
- **決策：** `accounting.js` 維護內部科目表，每筆分錄強制借貸平衡；資產購置、折舊／攤銷、保險應收、借款及報表以此為資料來源。
- **理由：** 讓營運現金流、損益和資產負債可在遊戲中對照，並提供可測試的財務資料結構。
- **代價：** 遊戲現金、存貨／負債與 accounting balances 是跨欄位的雙重呈現，所有變更路徑都需維持一致。
- **防線：** 主要營運路徑有勾稽測試；分錄不平衡不得被靜默忽略。
- **範圍界線：** 科目編碼屬本專案內部編號，報表只模擬主要呈列，不宣稱完整財報或法定合規。

## ADR-006｜攤型升級由安全條件與持續成本共同約束

- **狀態：** 已採用
- **決策：** 攤位依流動、固定、大排檔逐級升級；升級需滿足設備／規模條件，並伴隨容量、能源、保險及折舊等影響。
- **理由：** 將視覺擴張與風險、產能及持續成本相連，避免升級只帶來無條件收益。
- **代價：** 多店時需對每個 outlet 分別驗證安全、員工及保險資料。
- **重新評估條件：** 攤型或安全設備新增時，需一併更新資格檢查、UI 提示、記帳與測試。

## ADR-007｜不同業態的分店資料彼此區分

- **狀態：** 已採用
- **決策：** 分店商品、備料、價格、設備與升級菜色由 outlet 類別決定；店長自動化只處理例行營運，重大事件仍由玩家決定。
- **理由：** 讓併購、管理與品牌聯盟形成可辨識的業態策略，不讓所有分店使用同一張商品表。
- **代價：** 新增業態需同步新增產品資料、庫存正規化、UI 管理、事件處理及測試。
- **重新評估條件：** 分店數量或業態組合超出固定場景資料的合理範圍。

## ADR-008｜先以既有場景內的視覺成長反映進度

- **狀態：** 第一階段已完成；更大場景待評估
- **決策：** 主店尺寸／結構由攤型與 expansions 推導；併購透過既有鄰攤的亮度、標示與短暫接手回饋呈現。場景座標不寫入存檔。
- **理由：** 使用現有五攤資料與繪製管線，讓經營進度有視覺回饋，同時避免只擴畫地圖但沒有對應規則。
- **代價：** 店面可能會在固定地圖範圍內變大；可營運攤位數仍受既有資料限制。
- **後續方向：** 相機活動範圍與遠景補強屬下一階段；新增可探索區塊前，必須先定義可經營內容、路徑與存檔資料。

## ADR-009｜尊重作業系統減少動態效果偏好

- **狀態：** 已採用
- **決策：** 場景動畫可暫停；偵測到減少動態效果偏好時抑制動態更新，接手提示亦不播放位移淡出。
- **理由：** 動畫用於傳達經營狀態與場景生命感，不應凌駕使用者的系統設定。
- **重新評估條件：** 增加新的持續動畫或場景特效時，需保留等價靜態狀態與 reduced-motion 行為。
