# 遊戲雷達評估與改善紀錄

**檢視日期：** 2026-10-31  
**範圍：** 目前可執行的《夜嵐夜市》程式、存檔／引擎測試與維運文件。  
**評分方式：** 1–5 分，是以目前功能和可觀察程式行為所作的設計檢視，不是玩家留存、問卷或實機效能測量。本次沒有逐尺寸擷取畫面或進行實機聽感測試；未經量測的部分會明確標示，不將推測當成結果。

## 對整體 code review 建議的取捨

- **採納「進入收斂與打磨期」方向：** 先改善新手理解、節奏、情境回饋和效能量測，不再堆疊同量級的經營子系統。
- **本次採取小範圍改善：** 前夜現金簿摘要、週焦點門檻提示、投資固定成本預覽、恢復倒數、公開成就進度、跨期敘事／財報入口與連擊音階，均沿用既有經營規則，不新增經濟數值或存檔 schema 欄位。
- **下一個體驗優先項目：** 30 分鐘新手路徑及資訊分層。它預期比新增更多事件更能降低認知負擔；完成前應先觀察實際遊玩流程，再決定是否增加提示。
- **延後項目：** 引擎／測試拆檔、真正可探索的大地圖、多期角色支線、分享卡及動態競爭者；需分別估算回歸風險與認知負擔，不與本次混為一個大改版。

### 本次新增的回饋邊界

- 前夜摘要標示實際現金收入／支出及淨流入，與會計現金分錄一致；銷售、小費及活動是拆解數字，不把當晚預估當實收。
- 週決策的固定成本支應夜數是風險提示，不等同損益或現金流預測；標示未計的變動費用，避免假精確。
- 食安恢復倒數只呈現既有 `outbreakRecoveryUntilDay` 規則；沒有增加事故、延長恢復或另扣口碑。
- 成就進度僅提供單一明確的公開目標，隱藏故事解鎖前仍不透露進度。
- 音階連擊只影響提示音頻率，玩家靜音時也不會建立額外音訊效果。

## 本次改善的實作邊界

### 跨期敘事回聲

- 只在第 31、61、91 夜等新一期第一夜，讀取前一期結帳報告與該期最近一次週決策。
- 根據已記錄的期末結局及週決策，生成章節標題與一段短敘事；不改變當夜事件、現金、口碑或任何結帳金額。
- 資料由既有 `monthlyReports` 和 `decisions` 推導，不新增存檔欄位、不升級 schema；舊存檔缺少期末結局時，維持原本日曆文案。

### 可選港邊音景

- 使用瀏覽器 Web Audio API 程序化產生低音量濾波環境音，無外部音檔、套件或網路請求。
- 音效預設關閉，保留使用者既有音效偏好；玩家明確開啟後才在互動時建立音訊環境。
- 關閉時停止並釋放音景節點；分頁隱藏時暫停音訊處理。瀏覽器不支援 Web Audio 時不影響遊戲操作。

### 靜態場景繪製

- 活動場景維持既有動畫更新頻率。
- 暫停場景或系統偏好減少動態效果時，不再每個動畫影格都重繪完整畫面；改為最多每 100 毫秒繪製一次，讓靜態畫面和相機調整仍能更新。
- 這是針對可見工作量的保守降載，不代表已取得特定裝置的效能提升數據；實際改善仍需量測。

## 後續驗收建議

1. 跑完三期以上的同一存檔，確認不同結局會反映到下一期第一夜，期中夜仍使用既有活動日曆。
2. 在有／無 Web Audio 的瀏覽器測試開關、重新整理、靜音與分頁切換；確認無自動播放、錯誤或持續音訊。
3. 在一般營業、暫停及系統減少動態效果三種狀態檢視場景；相機操作和攤位點擊仍須可用。
4. 以桌機與手機錄製 60 夜以上遊玩流程，觀察故事重複感、店型策略差異、每晚操作耗時與畫面流暢度，再決定下一輪內容投資。
