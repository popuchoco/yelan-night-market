## 對整體 code review 建議的取捨

- **採納「進入收斂與打磨期」方向：** 先改善新手理解、節奏、情境回饋和效能量測，不再堆疊同量級的經營子系統。
- **本次採取小範圍改善：** 前夜現金簿摘要、週焦點門檻提示、投資固定成本預覽、恢復倒數、公開成就進度、跨期敘事／財報入口與連擊音階，均沿用既有經營規則，不新增經濟數值或存檔 schema 欄位。
- **第二輪已完成的 GAME RADAR 改善：** 成長決策使用每期保費攤提後的穩定固定承諾估算，展示七夜新增成本與每夜損益兩平貢獻門檻；週風險卡彙整事故、保障、理賠應收與下期保費，理賠收款則帶回事件專屬的改善敘事。三個固定亂數種子各完成保留現金、擴店／招募及投保／店長分店 60 夜 smoke，報表與分錄勾稽；這只驗證受控路徑可持續與帳務一致，不表示玩家留存或所有策略數值已經證明平衡。
- **持續中的體驗優先項目：** 30 分鐘新手路徑及真人／手機資訊密度驗收仍是產品優先方向。M10 工程交付及 M11 首個可經營區塊已完成，但實際手機觸控、玩家是否理解續航免責、風險卡收合的可發現性仍待真人驗收；不以自動化測試宣稱產品體驗已證明。
- **延後項目：** 真正可探索的大地圖、多期角色支線、分享卡及動態競爭者；需分別估算回歸風險與認知負擔，不與 M10 有限相機擴展混為一個大改版。

### 本次新增的回饋邊界

- 前夜摘要標示實際現金收入／支出及淨流入，與會計現金分錄一致；銷售、小費及活動是拆解數字，不把當晚預估當實收。
- 週決策的固定成本支應夜數是風險提示，不等同損益或現金流預測；標示未計的變動費用，避免假精確。
- 投資試算使用排除單夜天候、稽查、宣傳及清潔費的每夜固定承諾，保費按 30 夜攤提；損益兩平門檻只代表所需新增貢獻，仍須再扣食材與事件成本。
- 週風險摘要只讀取既有事故、保險快照與理賠應收；理賠收款的故事附註寫入當夜日記，不額外改變口碑、客流、保費或賠款。
- 風險卡以原生 disclosure 預設收合且只出現在週決策頁，降低昨夜現金簿、週焦點及投資預覽同屏的資訊量；固定承諾續航以醒目單行說明非保證估算範圍。
- 食安恢復倒數只呈現既有 `outbreakRecoveryUntilDay` 規則；沒有增加事故、延長恢復或另扣口碑。
- 成就進度僅提供單一明確的公開目標，隱藏故事解鎖前仍不透露進度。
- 音階連擊只影響提示音頻率，玩家靜音時也不會建立額外音訊效果。

## 大眾經營節奏差距與後續改善方向（2026-10-31）

這次產品比較聚焦於體驗結構，不把其他作品的角色、介面、規則或素材搬進本專案。核心判斷是：夜嵐的帳務可信度與經營深度已是特色，但新玩家第一眼容易先看到「要管理很多資料」，而不是「我正在照顧一間港邊小店」。優先補足外層的店面身份、短循環回饋和階段目標；內層會計與風險資料仍保留完整、可查。

| 體驗落差 | 玩家可能感受 | 低風險改善方向 | 不採取的捷徑 |
| --- | --- | --- | --- |
| 店面幻想被面板蓋過 | 場景像資料儀表板，擴張只是帳面變大 | 讓備料、缺貨、排隊、出餐與分店營業狀態有清楚的場景回饋；延續 M10／M11 已有成長場景 | 不先做更大的空地圖或不可經營的裝飾區 |
| 合胃口與備料配對不夠像主技能 | 出餐變成重複點擊，補貨像填表 | 每晚維持一至兩個有意義的菜色／庫存取捨；用既有顧客需求、庫存和服務結果加強即時視覺／音效，不先調經濟參數 | 不照搬貨架格子或新增大量菜色清單 |
| 長期目標不夠尖 | 30 夜後能繼續，但不確定本期值得記住什麼 | 7 夜結算聚焦現金流、週焦點與人物一句回饋；30 夜摘要先說人話，再讓玩家展開四大報表 | 不以破產或失敗扣款強迫製造刺激 |
| 人物關係薄於系統資訊 | 熟客容易只剩口碑／加成數字 | 後續集中打磨 3–5 位熟客／員工的跨夜回聲，優先用日記和現有經營結果推進 | 不再堆疊一批互不相連的隨機事件 |
| 新手一次看到太多規則 | 保險、報表、公告與成本預覽一起出現時不知先做什麼 | 開局七夜採漸進揭露與情境提示；帳務、保險仍可主動查看，不強制教學、不永久隱藏進階能力 | 不把專業資訊刪掉，也不做長篇必讀教學 |
| 成果不易帶走或回想 | 玩完一週／一期後缺少一句可記住的結果 | 後續可製作本機結果卡：店面風格、一期成果與代表故事；分享功能排在可讀性之後 | 不為話題性先做連線、互害或社群帳號 |

### 建議執行順序

1. **先驗收 M11 與資訊密度：** 用真實手機與真人流程確認昨夜現金簿、週焦點、投資預覽和收合風險卡是否仍造成擁擠，並直接詢問「續航夜數」是不是被理解為保證。這是觀察工作，不應由程式測試代替。
2. **下一個開發焦點放在開局七夜：** 以既有 `phase`、週焦點、公告與庫存推導「今晚一件事」，逐夜揭露需要的說明；不新增經濟規則或平行教學 state。操作提示可略過，遊戲說明仍可隨時查閱。
3. **再打磨配對短循環：** 強化「客人偏好 → 菜色／備料是否合適 → 出餐／缺貨結果」在場景中的可讀回饋。只改善呈現、動畫與音效；任何數值加成要另立平衡評估及借貸測試。
4. **之後才做週／期結果儀式：** 先提供一張簡潔摘要（現金變化、經營焦點、口碑／熟客變化、一句人物回聲），完整帳務報表維持次層展開，不把現金流、淨利與現金餘額混為一談。
5. **人物支線與本機分享卡列後續候選：** 先確認前三項已讓玩家知道下一步、感受到出餐結果、理解一週／一期成果，再增加少量跨夜角色內容；不以新增事件數量取代關係累積。

**驗收原則：** 新手在第一夜能無阻完成備料、開門與一筆出餐；前七夜每次只突出一個主要下一步，所有會計／保險細節仍可主動進入；週焦點提示不與公告／事件搶主視覺；短循環回饋不改營運金額；至少完成窄版 viewport、鍵盤操作及真實手機驗收後才關閉產品驗收項目。現階段沒有真人留存或裝置效能數據，不據此調高 GAME RADAR 評分。

## 本次改善的實作邊界

### 跨期敘事回聲

- 只在第 31、61、91 夜等新一期第一夜，讀取前一期結帳報告與該期最近一次週決策。
- 根據已記錄的期末結局及週決策，生成章節標題與一段短敘事；不改變當夜事件、現金、口碑或任何結帳金額。
- 資料由既有 `monthlyReports` 和 `decisions` 推導，不新增存檔欄位、不升級 schema；舊存檔缺少期末結局時，維持原本日曆文案。

### 可選港邊音景

- 使用瀏覽器 Web Audio API 程序化產生低音量濾波環境音，無外部音檔、套件或網路請求。
- 音效預設關閉，保留使用者既有音效偏好；玩家明確開啟後才在互動時建立音訊環境。
- 關閉時停止並釋放音景節點；分頁隱藏時暫停音訊處理。瀏覽器不支援 Web Audio 時不影響遊戲操作。

### 靜態場景繪製

- 活動場景維持既有動畫更新頻率。
- 暫停場景或系統偏好減少動態效果時，不再每個動畫影格都重繪完整畫面；改為最多每 100 毫秒繪製一次，讓靜態畫面和相機調整仍能更新。
- 這是針對可見工作量的保守降載，不代表已取得特定裝置的效能提升數據；實際改善仍需量測。

## 後續驗收建議

1. 跑完三期以上的同一存檔，確認不同結局會反映到下一期第一夜，期中夜仍使用既有活動日曆。

3. 在一般營業、暫停及系統減少動態效果三種狀態檢視場景；相機操作和攤位點擊仍須可用。
